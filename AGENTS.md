# AGENTS.md

Guidance for anyone (human or agent) changing PipDog: a macOS 14+ menu-bar app (LSUIElement, not sandboxed) that shows live picture-in-picture windows of other windows or regions.

## Repository layout

- `PipDog/App`: entry point, menu bar (`StatusMenu`), permissions, welcome window (`Onboarding`, `WelcomeView`).
- `PipDog/PiP`: `PiPManager`, `PiPPanel`, `PiPContentView`, `WindowCapture`, `SourceWindowActivator`, `HoverHider`, `SnapshotPreview`, resize handle.
- `PipDog/Settings`: shortcut, capture, click-mode, appearance and language settings, `SettingsView`, `SettingsActivation`, `LaunchAtLogin`.
- `PipDog/Input`: Carbon hotkeys, region selector, modifier + double-click event tap (`ClickTap`, `ClickTrigger`), `AXRegionFinder`.
- `PipDog/Support`: geometry, `WindowLocator`, `Feedback`, `KeyCodeNames`, `Timer.scheduledOnCommonModes`.
- `PipDog/Resources`: `Info.plist` (generated), entitlements, `Assets.xcassets` (`AppIcon`, template `StatusIcon`), String Catalogs `Localizable.xcstrings` and `InfoPlist.xcstrings`.
- `Design/`: `AppIcon-1024.png` and the scripts that draw it (`AppIcon.swift`) and the menu-bar icon (`StatusIcon.swift`). Not part of the app target.
- `Config/Signing.xcconfig`: signing defaults. `scripts/package.sh`: release packaging.
- Docs: `README.md` (English, default) and `README.zh-CN.md` (Simplified Chinese) are the user guide and must say the same thing; `docs/DEVELOPMENT.md` (Chinese) holds implementation details, detailed behaviour, settings keys, signing and packaging. Update all three when user-visible behaviour changes.
- `LICENSE` (Apache-2.0, unmodified official text) and `NOTICE` (copyright line).

## Build and verify

- The project is generated by XcodeGen. After editing `project.yml` or adding/removing source files, run `xcodegen generate`; never hand-edit `PipDog.xcodeproj` or `Info.plist`.
- Before every commit: `xcodebuild -scheme PipDog -configuration Debug -derivedDataPath build build` must succeed with zero Swift warnings.
- Swift 6 with strict concurrency. UI text is localized (English source, Simplified Chinese translation; see Localization); code comments may be Chinese.
- Public APIs only. If a private API (e.g. SkyLight) is ever unavoidable, isolate it in one file and explain why.

## Conventions

### Concurrency
- UI, settings and capture state are `@MainActor`. In `WindowCapture` only the SCStream frame/stop callbacks are `nonisolated`; they touch only the thread-safe `FrameMailbox` and hop back with `DispatchQueue.main.async`. Don't create a Task per frame.
- Stream configuration changes go through `setNeedsUpdate()`, which builds a fresh `SCStreamConfiguration` with `makeConfiguration()`; never mutate a configuration that is being applied. Output size is capped by the panel's pixel size (long edge ≤ 4096, times zoom, never above native).
- Carbon hotkey callbacks run on the main run loop: use `MainActor.assumeIsolated`.
- `ClickTap` runs on its own thread and may only use its lock-protected state; dispatch to main for anything else. No tap is installed while the feature is off; `ClickTrigger` re-checks Accessibility every second and falls back to listen-only when it's revoked.
- AX queries (`AXRegionFinder`, window matching in `SourceWindowActivator`) run off the main thread with time limits, so a hung target app can't freeze PipDog.
- Timers always use `Timer.scheduledOnCommonModes` (main run loop, `.common` modes). `Timer.scheduledTimer` stops firing while menus, `runModal` alerts or slider drags are tracking.

### Localization
- Every user-visible string goes through the String Catalog and must exist in both English and Simplified Chinese: menu, settings, welcome window, alerts, `Feedback` notices, pause overlay, permission texts, About, and Info.plist usage descriptions (`InfoPlist.xcstrings`). Never hardcode Chinese in Swift.
- Write the English source in code: `String(localized:)` for AppKit and plain `String`s; SwiftUI string literals (`Text`, `Button`, `Section`, `Toggle`, `Picker`, `LabeledContent`, `.help`) are already `LocalizedStringKey`. Passing a `String` variable to `Text` doesn't localize, so localize it first; use `Text(verbatim:)` for numbers, fps and key symbols.
- Add the zh-Hans translation to `Localizable.xcstrings` in the same change. Interpolations are `%@` (String) and `%lld` (Int) in keys; use positional `%1$@`, `%2$@` in translations with several arguments.
- Don't assemble sentences from fragments: write a full sentence per variant (click / double-click, on / off), or insert only whole words. Join lists with the `list.separator` key.
- English uses Apple's terms: System Settings, Privacy & Security, Screen & System Audio Recording, Accessibility, Login Items & Extensions, Open at Login. Chinese uses the System Settings names (系统设置 › 隐私与安全性 › 辅助功能).
- Text persisted across launches stores a reason code, not localized text. NSLog stays English and untranslated.
- The language setting (`LanguageSettings`) writes or removes `AppleLanguages` in the app's own domain and offers `Permissions.relaunch()`; Restore Defaults sets it back to Follow System.
- After a build, the keys in the `*.stringsdata` files under `build/Build/Intermediates.noindex` must match the catalog's keys, the app must contain `en.lproj` and `zh-Hans.lproj`, and `grep -rn '[一-龥]' PipDog` may only find comments and the language picker's 简体中文.

### Permissions
- Ask only when a feature needs it; never prompt at launch. Read the Screen Recording preflight once at launch as a snapshot, and don't gate PiP on preflight: attempt capture and trust the result (a successful capture wins over a stale preflight; an explicit `userDeclined` clears it).
- Screen Recording: call `CGRequestScreenCaptureAccess` at most once per run and never together with a custom alert. The first denied PiP calls it and shows a `Feedback`; later failures and menu clicks show `Permissions.showAlert`, which offers a relaunch (`createsNewApplicationInstance = true`; quit the old instance only after the new one launched). Use `Permissions.screenRecordingName` for the System Settings name (macOS 15+: Screen & System Audio Recording). `Permissions.isScreenRecordingLost` also treats "had permission at launch, preflight now false" as revoked.
- Accessibility: prompt only with `AXIsProcessTrustedWithOptions` (it registers PipDog in the list), once per run per feature, then use `Feedback`. Launch and switching back to the source never request it.

### Menu bar, settings and focus
- Menu bar is AppKit `NSStatusItem` + `NSMenuDelegate.menuNeedsUpdate` (re-reads permissions and settings each time), not `MenuBarExtra`. Its icon is the template image from `StatusMenu.icon(size:)`, also used inline in the welcome window.
- `SettingsActivation.open(returningTo:)` owns the single settings window: switch to `.regular`, `orderFrontRegardless()`, then `NSApp.activate()` + `makeKeyAndOrderFront`, and retry activation once on the next run-loop turn. No `ignoringOtherApps`. On close, go back to `.accessory`, cancel shortcut recording and hand focus back to the previous app (`yieldActivation(to:)` + `activate(from:)`, or `NSApp.deactivate()`). The SwiftUI `Settings` scene only hosts ⌘, and redirects via `SettingsRedirect`.
- The welcome window (`Onboarding`) is one reusable non-modal NSWindow showing `WelcomeView`, which takes plain `WelcomeInfo` data so it can be rendered standalone. Shown once (UserDefaults `PipDog.onboardingShown`) and from the Welcome Guide… menu item. Launch notices run in order from `AppDelegate`: welcome window closes → leftover parked-window notice → 3 s → hotkey registration failures.
- User-facing errors use `Feedback.show(...)`; missing permissions use `Permissions.showAlert(...)`. Show the cause and next step, localized; raw errors and OSStatus codes go to NSLog only.

### PiP panel
- One close path: `PiPPanel.close()` → `WindowCapture.stop()` → `onClose` removes it from `PiPManager`; unexpected capture ends use it too. `hidesOnDeactivate = false`.
- The panel never takes keyboard focus (`canBecomeKey` only while `SnapshotPreview` shows Quick Look). No `isMovableByWindowBackground`: `PiPContentView` drags after ≥ 4 pt of movement, otherwise it's a click.
- Click mode (`WindowClickSettings`, single or double, default double) is read on every `mouseUp`; clicks are counted in series split by whether ⌥ is held. ⌥-click is Quick Look; ⌘-click only resets zoom.
- Zoom/pan only moves `imageLayer` (zPosition −1); chrome subviews (pause overlay, resize handle, ×, `ZoomBadge`) never scale. Zoom settling calls `PiPPanel.contentSizeDidSettle()` to raise capture resolution.
- Appearance: change opacity only through `PiPAppearanceSettings.setOpacity(_:)`; under `@Observable`, never assign a property inside its own `didSet`. `HoverHider` fades a panel out after 1.5 s and makes it click-through; it comes back when the pointer leaves or on a lone ⌥ tap (no mouse/key down, no other modifiers, no non-modifier key held per `CGEventSource.keyState`).
- Pause overlay: source app hidden, or source window minimized (checked every second; `WindowLocator.isOnScreen`, then AX `kAXMinimizedAttribute`, only with Accessibility). Don't infer pauses from "no new frames" or other Spaces; that flickers.
- Quick Look snapshots come from the running stream (`WindowCapture.snapshot()`), never `SCScreenshotManager` or a second stream (a second session on the same window fails). PNGs live in `$TMPDIR/PipDog` and are deleted on replace, launch and quit.

### Source window: switching back and edge parking
- Never hide the source app or move it fully off screen: hiding stops ScreenCaptureKit capture and some apps stop drawing off screen. `WindowCapture` must treat a hidden app's stopped stream as paused, not closed, and resume after unhide.
- `SourceWindowActivator.toggle` decides from current state, not click counts: if the source is frontmost, park it with AX at the screen's right edge (left if another screen is to the right), leaving a 1-pt sliver, recording the original position and the exact AX window moved; otherwise move it back (confirm the position before forgetting it) and bring it to front. Moves are verified against `WindowLocator` (up to ~1 s for slow apps) and undone if the wrong window moved. Don't change the park geometry.
- Parking and moving back need Accessibility; without it, only show a notice. Parked windows are restored when their last PiP closes, on quit and before a permission relaunch (synchronously, via `restoreAllStashed()`); anything left over is saved and reported on the next launch.
- `bringToFront` unhides the app, uses cooperative activation, and raises the exact window by AX (position/size, then title) only when Accessibility is already granted.

### Launch at login
- Only `SMAppService.mainApp` `register()`/`unregister()`; `status` is the source of truth (nothing in UserDefaults). Never register at launch. Explain `.requiresApproval` (System Settings › General › Login Items & Extensions) and `.notFound` (install in Applications). Restore Defaults doesn't touch it.

### Signing, packaging and icons
- Signing lives in `Config/Signing.xcconfig` (never in `project.yml`); local overrides go in the untracked `Config/Signing.local.xcconfig`. Hardened Runtime is on: add entitlements when adding capabilities that need them.
- Package with `./scripts/package.sh` (universal Release, zip + dmg in `build/dist/`, log in `build/xcodebuild.log`; optional notarization via `SIGN_IDENTITY` + `NOTARY_PROFILE`). Never print secrets; notarization credentials live only in a notarytool keychain profile. `build/` is not committed.
- App icon: regenerate `Design/AppIcon-1024.png` with `swift Design/AppIcon.swift Design/AppIcon-1024.png`, then the `AppIcon.appiconset` sizes with `sips` (see `docs/DEVELOPMENT.md`). Menu-bar icon: `swift Design/StatusIcon.swift PipDog/Resources/Assets.xcassets/StatusIcon.imageset` (18 pt template; no dog at @1x).

## Git commits

- Use [Conventional Commits](https://www.conventionalcommits.org/), in English: `<type>(<optional scope>): <summary>`.
- Types: `feat`, `fix`, `docs`, `style`, `refactor`, `perf`, `test`, `build`, `ci`, `chore`. Pick the primary type when a commit mixes changes. Optional scopes name the area, e.g. `pip`, `settings`, `onboarding`, `icon`, `readme`.
- Summary: imperative mood, lowercase, no trailing period; the whole subject line is at most 72 characters.
- Leave a blank line, then explain what changed and why, plus any compatibility notes. Don't restate the diff file by file. Keep identifiers and paths as-is, in backticks.
- For multi-topic commits, group changes as `1.`, `2.`, each group heading ending with a colon; items use a three-space indent plus `- `, with continuation lines aligned.
- When persistence, formats or shared fields change, describe old data, missing fields and how upgrades stay compatible. For UI changes, end the body with what users will see and where.
- Don't include unrelated changes, debug leftovers or credentials, and avoid empty phrases like "final version" or "changes as requested".
- Never push without the owner's approval. Never amend, squash, rebase or force-push without explicit confirmation.

Template (trim as needed):

```text
<type>(<scope>): <imperative lowercase summary>

<What changed and why; what it affects>

1. <First group of changes>:
   - <Key behaviour and compatibility notes>

2. <Second group of changes>:
   - <Key behaviour and impact>

<User-visible change and where to find it; omit if none>
```

Examples:

```text
fix(pip): show the pause overlay only for minimized windows
feat(settings): add opacity and hover-to-hide options
docs(readme): add Gatekeeper steps for unnotarized builds
```
