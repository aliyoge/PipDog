# PipDog 开发说明

面向开发者的完整说明：技术栈、构建、签名打包、图标，以及每个功能的详细行为。用户说明见 [README.md](../README.md)（[简体中文](../README.zh-CN.md)）；代码约定见 [AGENTS.md](../AGENTS.md)。


## 技术栈
- Swift 6 + SwiftUI（设置）+ AppKit（菜单栏、NSPanel 浮窗）
- ScreenCaptureKit 实时抓取窗口画面
- Carbon `RegisterEventHotKey` 全局快捷键（不需要额外权限）
- CGEventTap（跑在独立线程上，不受主线程卡顿影响）：修饰键 + 双击触发，并拦截触发用的那次点击（需要辅助功能权限）
- 辅助功能（Accessibility）接口：修饰键 + 双击时找鼠标下方的界面元素；点 PiP 切回原窗口时（默认双击，可改单击；有权限才用）把那个窗口提到最前；再点一次时把原窗口移到屏幕边上、再移回来
- Quick Look（`QLPreviewPanel`）：⌥ + 单击 PiP 看原尺寸截图（从正在运行的抓取流里取一帧原生分辨率画面，不另开截图会话）
- 只用公开 API（CGWindowList、ScreenCaptureKit、AXUIElement、CGEventTap、QuickLookUI）
- 工程由 [XcodeGen](https://github.com/yonaskolb/XcodeGen) 从 `project.yml` 生成，`.xcodeproj` 不手改
- 界面文字用 String Catalog：`PipDog/Resources/Localizable.xcstrings`（代码里的文字）和 `InfoPlist.xcstrings`（Info.plist 里的权限说明）。源语言英文，另有简体中文（zh-Hans）

## 开发
```sh
xcodegen generate          # 改了 project.yml 或增删文件后重新生成
open PipDog.xcodeproj      # 或命令行构建：
xcodebuild -scheme PipDog -configuration Debug -derivedDataPath build build
open build/Build/Products/Debug/PipDog.app
```
启动时不弹任何授权框，权限都是用到时才引导：

- **屏幕录制**（macOS 15+ 叫「屏幕与系统录音」）：PiP 时总是直接尝试抓取。本次运行第一次因没权限失败时，PipDog 让系统弹出授权框（同时把 PipDog 登记到系统设置的列表里），并在屏幕顶部提示去哪里打开；之后再失败会弹出说明框，带「打开系统设置」「重新启动 PipDog」「取消」。运行中授权后要重新启动 PipDog 才生效，这时说明框会直接提示「已授权，需要重新启动」。即使系统暂时仍显示未授权（macOS 15 偶尔如此），也可以直接点「重新启动 PipDog」。重启先启动新实例，成功后才退出旧的；失败只提示，不退出。
- **辅助功能**：修饰键 + 双击，和「再点一次小窗（默认双击）把原窗口移到屏幕边上」需要（点小窗切回原窗口时有权限就顺便用来提起具体窗口，没有也不会弹框）。在设置里打开双击功能而缺权限时，或功能已开启、本次运行第一次做这个手势时，弹出系统的辅助功能授权框；本次运行第一次因缺权限移不了窗口时也一样（这样 PipDog 会出现在系统设置的辅助功能列表里）；之后只显示简短提示。启动时、点小窗切回原窗口时都不弹框。运行中授权后会自动生效并提示一次。
- **菜单**里显示两项权限的当前状态（每次打开菜单都会重新读取）：屏幕录制（macOS 15+ 显示为「屏幕与系统录音」）「已授权 / 未授权 / 已授权，需重新启动」，辅助功能「已授权 / 未授权（移到屏幕边上、修饰键 + 双击需要）」。点未授权的项会弹出对应引导，点「需重新启动」会确认后重启。屏幕录制在本次运行成功抓取过以后就显示已授权；如果运行中撤销了权限，要等下一次 PiP 失败后才会变回未授权。

现在用固定的开发者证书签名，重新构建后这些权限一般会保留（之前签过 ad-hoc 版的话，可能需要在权限列表里删掉旧条目重新授权一次）。

## 本地化

所有界面文字（菜单、设置、欢迎窗口、弹框、提示浮层、暂停提示、权限说明、关于、Info.plist 的权限用途说明）都走 String Catalog，**英文和简体中文都要有**，不能在代码里写死中文。

- 代码里写英文源文本：AppKit / 普通 `String` 用 `String(localized: "…")`；SwiftUI 的 `Text("…")`、`Button("…")`、`Section("…")`、`Toggle("…")`、`.help("…")` 等字面量本身就是 `LocalizedStringKey`。传 `String` 变量给 `Text` 不会翻译，所以变量要先用 `String(localized:)` 取好；不用翻译的（数字、fps、快捷键符号）用 `Text(verbatim:)`。
- 在 `Localizable.xcstrings` 里给每个键补 zh-Hans。插值在键里写成 `%@`（String）、`%lld`（Int）；多个参数时中文用 `%1$@`、`%2$@`，可以调整顺序。
- 不要拼句子：不同说法（单击 / 双击、打开 / 关闭）各写一整句，或者只插入完整的词（例如 `Couldn't %@ Open at Login` 里的 turn on / turn off，中文为 打开 / 关闭）。列表分隔符用 `list.separator`（英文 `, `，中文 `、`）。
- 菜单里的权限名用 `Permissions.screenRecordingName`（英文 Screen Recording / Screen & System Audio Recording，中文 屏幕录制 / 屏幕与系统录音）。系统设置路径用系统里的叫法：英文 System Settings › Privacy & Security › Accessibility，中文「系统设置 › 隐私与安全性 › 辅助功能」。
- 需要跨启动保存的提示（上次退出留下的窗口）存原因，启动时再按当时的语言取文字。
- NSLog 只写英文，不翻译；代码注释可以是中文。
- 检查：构建时 `SWIFT_EMIT_LOC_STRINGS=YES` 会在 `build/Build/Intermediates.noindex/.../*.stringsdata` 里列出代码用到的键，和 `Localizable.xcstrings` 的键应该一一对应；`build/Build/Products/Debug/PipDog.app/Contents/Resources/` 里应有 `en.lproj` 和 `zh-Hans.lproj`。在 Swift 源码里搜汉字（`grep -rn '[一-龥]' PipDog`），除了注释和语言选择器里的「简体中文」不应再有。
- 用 `-AppleLanguages '(zh-Hans)'` / `'(en)'` 启动可以临时切换语言。

## 应用图标
- 原图在 `Design/AppIcon-1024.png`（1024×1024 透明 PNG，图标主体约 824×824，符合 macOS 图标网格）：浅灰底、石墨色大窗口描边，右下小窗里一只垂耳小狗。由 `Design/AppIcon.swift` 画出来，改配色或形状后运行 `swift Design/AppIcon.swift Design/AppIcon-1024.png` 重新生成原图。
- `PipDog/Resources/Assets.xcassets/AppIcon.appiconset` 里是各尺寸（16–512 的 @1x/@2x）。换图标时替换原图后重新生成：
  ```sh
  cd PipDog/Resources/Assets.xcassets/AppIcon.appiconset
  for s in 16 32 128 256 512; do
    sips -z $s $s ../../../../Design/AppIcon-1024.png --out icon_${s}x${s}.png
    sips -z $((s*2)) $((s*2)) ../../../../Design/AppIcon-1024.png --out icon_${s}x${s}@2x.png
  done
  ```
- 菜单栏图标是资源目录里的模板图 `StatusIcon`（单色，系统按菜单栏深浅着色）：大窗口描边 + 右下实心小窗，@2x 的小窗里镂空一只垂耳小狗（@1x 像素太少，只保留实心小窗）。由 `Design/StatusIcon.swift` 生成：`swift Design/StatusIcon.swift PipDog/Resources/Assets.xcassets/StatusIcon.imageset`。

## 签名
- 默认值在 `Config/Signing.xcconfig`（已提交）：`Apple Development` 证书、团队 `653QLVW4RT`、手动签名、开启 Hardened Runtime、非沙盒。Release 不带 `get-task-allow`。
- 本机想换证书或团队时，新建未跟踪的 `Config/Signing.local.xcconfig` 覆盖即可（已在 `.gitignore`），例如：
  ```
  CODE_SIGN_IDENTITY = Developer ID Application
  DEVELOPMENT_TEAM = XXXXXXXXXX
  ```
- 查看本机可用证书：`security find-identity -v -p codesigning`。

## 打包
```sh
./scripts/package.sh
```
会构建 Release（通用二进制 arm64 + x86_64），校验签名（`codesign --verify --deep --strict`），打印 Gatekeeper 评估（`spctl`），并生成：
- `build/dist/PipDog-<版本>.zip`
- `build/dist/PipDog-<版本>.dmg`（里面有拖到 Applications 的快捷方式）

注意：
- 完整构建日志写在 `build/xcodebuild.log`；构建失败时脚本会打印日志最后 40 行并退出。
- 装了 xcodegen 时脚本会先运行 `xcodegen generate`。如果 `project.yml` 和已提交的 `PipDog.xcodeproj` 不一致，这一步会改动工程文件（`git status` 里能看到）。

版本号取 `project.yml` 里的 `MARKETING_VERSION`。

用 Apple Development 证书签的包 **没有公证**：`spctl` 会显示 rejected，这是正常的。在自己的 Mac 上可以直接用；发给别人时对方需要右键 › 打开，或在「隐私与安全性」里点「仍要打开」。

### 以后换成 Developer ID 并公证
1. 在 Apple 开发者账号里创建 **Developer ID Application** 证书并装进钥匙串。
2. 保存公证凭据（只需一次，密码会存进钥匙串，不会写进仓库）：
   ```sh
   xcrun notarytool store-credentials pipdog-notary --apple-id <Apple ID> --team-id <团队 ID>
   ```
3. 打包时指定身份和凭据名：
   ```sh
   SIGN_IDENTITY="Developer ID Application: 名字 (团队 ID)" NOTARY_PROFILE=pipdog-notary ./scripts/package.sh
   ```
   脚本会用 hardened runtime 加时间戳重新签名，用 `notarytool submit --wait --output-format json` 提交 app 和 dmg 去公证，并检查返回的状态：不是 `Accepted` 就打印 `notarytool log` 的内容并退出；通过后用 `stapler staple` 把票据装订进去。也可以在 `Signing.local.xcconfig` 里改默认身份。

## 行为细节
以下是默认快捷键，都可以在「设置…」（菜单栏 › 设置…，⌘,）里修改：

| 快捷键 | 作用 |
| --- | --- |
| ⌃⌥P | PiP 当前聚焦的整个窗口 |
| ⌃⌥⇧P | 框选区域 PiP |
| ⌥⇧ + 双击 | PiP 鼠标下方的区域（如日志面板、聊天框） |
| ⌃⌥⌫ | 关闭所有 PiP |
| 双击小窗（可在设置里改成单击） | 切回原窗口；原窗口已在最前时再双击，把它移到屏幕边上（小窗画面照常更新），再双击移回原位 |
| ⌥ + 单击小窗 | 用快速查看看原尺寸截图 |
| 在小窗上 ⌘ + 滚动 / 捏合 | 以鼠标为中心放大画面（1–20 倍）；放大后滚动或拖动是平移画面，⌘ + 拖动框选放大，⌘ + 双击恢复原大小 |
| 小窗左上角 ×（鼠标移上去才显示） | 关闭这个 PiP（关闭全部用 ⌃⌥⌫） |

- 可以同时开多个 PiP，新小窗会错开摆放，并出现在原窗口所在的屏幕上（找不到时用鼠标所在的屏幕）。对同一个窗口或同一块区域再次触发，只会把已有小窗提到前面。
- **PiP 当前窗口**：PiP 的是最前面那个 app 的窗口。如果最前面的 app 没有可以 PiP 的窗口，只会提示，不会去抓别的 app 的窗口。选目标的候选窗口按参照实现（my-window-pip 的 `ShareableContentStore.isCandidate`）过滤子窗口 / 浮层：只要 layer 0 的普通窗口，所属 app 必须在运行且没被隐藏，菜单栏 app（accessory）和未知类型要有窗口标题，Dock 图标这类内部窗口（prohibited）一律不要，边长至少 80 点，没有标题的窗口面积还要有 200×200 点以上（过滤规则在 `WindowLocator.isCandidateWindow`，只影响选目标时的候选，不影响已经打开的小窗）。
- **框选区域**：按 ⌃⌥⇧P 后所有屏幕变暗，拖出一个矩形（小于 20 点的忽略），松开即 PiP；按 Esc、点右键、再按一次框选快捷键，或切到别的 app 都会取消。PiP 的是选区中心下方最上层的那个窗口，选区超出窗口的部分会被裁掉。之后即使原窗口被挡住或移动，小窗显示的仍是该窗口里的同一块区域（窗口缩到这块区域已经落在窗外时，整块区域会被移回窗口内，不会停在最后一帧）。
- **⌥⇧ + 双击**：用辅助功能接口找到鼠标下方合适的容器（滚动区、文本区、网页、表格、列表等，至少 120×60 且不是几乎整个窗口）；找不到时取以点击处为中心的 480×300 区域。触发用的第二次点击会被 PipDog 拦下，不会传给目标 app（第一次单击仍会照常传过去）。需要辅助功能权限；没授权时只能旁观、双击仍会传给目标 app，本次运行首次手势用系统授权框引导，后续只显示提示。授权后约 1 秒内自动切换成拦截模式，并提示一次；运行中撤销权限会自动退回旁观模式，并提示一次。在设置里关掉这个功能后，PipDog 完全不再监听鼠标。
- **双击小窗**（默认；设置 › 小窗里可以改成单击，下面说的「单击 / 再单击」指你选的那种点法，改了立即对已打开的小窗生效）：激活原窗口所在的 app（PipDog 先短暂接过前台再交给它，macOS 14+ 的协作激活要求这样做；原 app 已经在前台时不切换）。有辅助功能权限时，再把原窗口本身提到最前（按原窗口当前的位置和大小在该 app 的窗口里找，误差 2 点以内；查询在后台进行，最多约 0.5 秒；位置大小相同的窗口有多个时再按窗口标题区分）；没有权限、原窗口已最小化或没找到时，只激活 app，不弹任何授权框。没有辅助功能权限时，如果你正在用同一个 app 的另一个窗口，PipDog 切不到这个指定窗口，只会提示需要辅助功能权限。原 app 被隐藏时（你按了 ⌘H 或在 Dock 里隐藏），单击会先取消隐藏再切过去。按下后移动不到 4 点就松开才算点击，超过就是拖动小窗，不会切走；拖缩放手柄、点 × 也不算。双击模式下单独点一下什么都不做，快速连续双击两次也算两次（切回后马上再双击会移到旁边；但移动途中的点击会被忽略，见下一条）；单击模式下快速连点时每一下都算一次。⌥ + 单击在两种模式下都是快速查看，⌥ + 连点只算第一下；⌥ 点击和普通点击连着点时，换了一种就重新计数（⌥ 点一下后马上不按 ⌥ 双击，仍算一次双击）。
- **再点一次移到旁边**（默认双击）：如果原窗口已经是屏幕上最前面的窗口，单击小窗会把这个窗口移到它所在屏幕的右边缘外，只留 1 点在屏幕内（右边紧挨着另一块屏幕时改放左边缘），大小和高度位置不变。窗口没有隐藏、app 也没有隐藏，所以抓取不停，小窗画面照常更新（例如视频继续播放）。移走后前台和键盘交给下面那个窗口（没有别的窗口时交给访达），接着打字不会输进屏幕外的窗口。再单击小窗，窗口先移回原位（确认移回后才忘掉原位置；移回失败会提示，下次单击再试），再切到前台；没有辅助功能权限时只提示，不切过去（免得键盘输进屏幕外的窗口）。移回时用的是停放时移动的那个窗口；同一个 app 有好几个位置、大小、标题都一样的窗口而分不清时，PipDog 宁可不动也不移错，并检查实际移动的是不是这个窗口，移错了会放回去（反应慢的 app 会多等到约 1 秒再判断，不会把移对了的窗口撤回）。移动途中（通常不到 0.3 秒，反应慢的 app 最多约 1 秒）的点击会被忽略，所以快速连续双击时第二次可能不起作用，要等窗口移完再双击。这个窗口的最后一个 PiP 关闭时（同一窗口的整窗和区域 PiP 都关了），还停在屏幕边上的窗口会放回原位；退出 PipDog、或权限引导里点「重新启动 PipDog」时，也会先把还停在屏幕边上的窗口放回去（你自己挪走的不动；正在移过去的窗口会先等它移完，最多约 1 秒）。有窗口没能放回时（例如没有辅助功能权限），下次启动 PipDog 会提示有窗口可能还在屏幕边上，点小窗或自己拖回来即可。窗口几乎完全在屏幕外却没有记录时（例如 PipDog 异常退出过），单击会把它拉回屏幕内，而不是再移走一次。你自己把窗口挪走后，就不再当作被移走的窗口。是否移走只看原窗口当前是不是在最前，不数单击次数：你自己切到别的窗口后再单击，会切回原窗口。移动窗口需要辅助功能权限；本次运行第一次缺权限时弹出系统授权框，之后只提示，不会隐藏 app。
- **原 app 被隐藏（⌘H / Dock）**：小窗一直留在屏幕上：app 隐藏后系统会停掉对它窗口的抓取，小窗停在最后一个画面，并盖上「原 app 已隐藏，画面暂停 / 双击小窗恢复」的提示（设置成单击时显示「单击小窗恢复」）；双击（或单击，按设置）小窗，或从 Dock / ⌘Tab 切回这个 app，就取消隐藏，PipDog 重新开始抓取，画面恢复。隐藏期间 ⌥ + 单击看到的是停住的那个画面。取消隐藏后约 1 秒内没能恢复抓取时，暂停提示保留并提示可以再点小窗重试（提示里按设置说「单击」或「双击」）。只有原窗口关闭（app 还在）时小窗才会关闭；原 app 退出时不关，等它重启后重连（见下一条）。
- **⌥ + 单击小窗**：给原窗口拍一张原生分辨率的截图（区域 PiP 只截那块区域，放大时只截当前可见区域，不受小窗大小和 4096 上限影响；画面直接从这个小窗正在用的抓取里取：临时切到原生分辨率取一帧，再切回来，小窗可能闪一下变清晰；画面静止或原 app 已隐藏、1.5 秒内等不到原尺寸新帧时，用小窗当前的画面，可能不是原生分辨率），存成 PNG 放在临时目录 `$TMPDIR/PipDog`，用快速查看打开。打开前 PipDog 会临时切到前台；按空格或 Esc 关闭快速查看后，如果 PipDog 还在前台，就把前台还给之前的 app；快速查看没能打开、或你切到别的 app 让它自动收起时也一样收尾，小窗恢复成不接收键盘。快速查看开着时 ⌥ + 单击另一个小窗会换成那张截图。新截图会删掉上一张，退出 PipDog 时删掉整个目录。截图失败（例如原窗口已不可见、没有屏幕录制权限）时在屏幕顶部提示原因。
- **关闭单个小窗**：鼠标移到小窗上时左上角出现 ×，点它只关这一个；移开后 × 隐藏。关闭全部用 ⌃⌥⌫。
- **不抢键盘**：按下、拖动、单击小窗都不会把键盘焦点拿走，拖完小窗可以直接继续在原来的 app 里打字（小窗没有键盘操作；只有 ⌥ + 单击打开快速查看期间临时接收按键，Esc / 空格只关快速查看）。
- **放大和平移**：缩放和平移都在采集端裁剪，小窗里的画面始终 1:1 显示。在小窗上按住 ⌘ 滚动鼠标滚轮或触控板（方向跟随系统的「自然滚动」设置）、或捏合，以鼠标所在处为中心放大缩小画面（1–20 倍），放大缩小的是画面，不是小窗；按住 ⌘ 拖出一个矩形，松开后放大到框住的那块区域（保持小窗宽高比，框里的内容全部可见）。放大后滚动（方向跟随「自然滚动」）或拖动是平移画面（不会拖出画面边界），要移动小窗就先缩回原大小再拖。放大时小窗左下角显示当前倍数（如「2.5×」）；⌘ + 双击小窗一步恢复原大小（只复位，不切回原窗口）。拖动、平移、滚动和 ⌘ 手势都不算切回用的点击；×、缩放手柄、倍数和暂停提示不跟着缩放。缩放小窗时保持放大倍数和位置。缩放 / 平移停下约 0.25 秒后才更新抓取（防抖），输出像素是可见区域乘屏幕像素比例，不超过可见区域的原生分辨率和 4096；区域 PiP 的放大不超出那块区域，原窗口变小时可见区域跟着裁回窗口内。
- **不透明度和悬停隐藏**：设置 › 小窗里可以调小窗的不透明度（30%–100%，默认 100%）。「悬停时自动隐藏」默认关闭；打开后，鼠标在小窗上停约 1.5 秒，小窗淡出并让点击穿透到下面的窗口，方便点被挡住的东西；鼠标移出小窗的范围就淡入恢复。小窗隐藏时单独按一下 ⌥（按下后 0.5 秒内松开，中间不点鼠标、不按别的键；⌥ + E 这类组合字符不算）会立即恢复，并且在鼠标移出之前不再隐藏；按住 ⌥ 点击、拖动下面的 app（终端里移光标、浏览器里下载链接等）照常穿透，不会让小窗恢复。恢复后可以照常点小窗（切回、⌥ + 单击、×、缩放）；再次 PiP 同一个窗口也会让它恢复。在小窗上按下、滚动或捏合后，这次悬停也不会再隐藏，直到鼠标移出；按住 ⌥、指着 × 或缩放手柄时不隐藏；新小窗出现在鼠标下面、或按着鼠标（拖文件等）经过小窗时，要等鼠标移出再进来才开始计时。关掉这个选项会立即恢复已隐藏的小窗。
- **悬停控制条**：鼠标移到小窗上时，顶部淡出一条控制条（`PiPControlBar`，内容视图的子视图，和 ×、倍数提示一样不随缩放变化）：暂停 / 继续、帧率、恢复原大小、悬停时自动隐藏、关闭。只有按钮接收点击（`hitTest` 只返回可用按钮），空白处的事件落到内容视图，所以按住控制条空白处拖动是移动小窗（放大时也不平移画面），点一下不算「切回原窗口」的点击（`PiPContentView.startedOnControlBar`）；面板很窄时按钮和间距按比例缩小并裁在控制条内（`buttonClip`），不会画到左上角的 × 上。指着按钮时高亮并在下方显示名称（自绘的 `ControlBarHint`，不用系统 tooltip：面板是浮动层，tooltip 会被压住而且有延迟）。控制条算 chrome：`PiPContentView.isOverChrome` 把控制条和它的名称提示都算进去，指针停在那里时 `HoverHider` 到点不淡出；指针离开小窗（或小窗淡出）时控制条跟着隐藏。暂停复用「原 app 隐藏」那套语义（`WindowCapture.pauseUntilShown()` / `resumeAfterUnhide()`，保留最后一帧），状态记在 `PiPPanel.userPaused`，和隐藏、最小化、重连等待互不干扰：那几种状态的遮罩优先，暂停按钮禁用；用户暂停期间原 app 的隐藏 / 恢复只更新遮罩，不会擅自恢复画面。只有真正恢复成功才清暂停；恢复途中状态又变了（用户又点了暂停、原 app 又隐藏 / 最小化、开始重连）会把刚开起来的流再停上，遮罩和画面不会一个说暂停、一个还在动。帧率按钮按 `CaptureSettings.frameRateOptions` 循环，能拿到 bundle ID 时写进这个 app 的记录（设置里的「按 App 帧率」会多一行），否则改全局默认；自动隐藏按钮改的就是那个全局开关。
- **键盘控制**（默认关闭，`PipDog.enhancedMode`）：两件事只能靠 CGEventTap 做——Carbon 的 `RegisterEventHotKey` 注册不了 fn 修饰键，悬停裸键也只在指针停在小窗上时才该拦。tap 在 `EnhancedHotKeys` 里，和 `ClickTap` 同一套做法：自己的线程和 run loop（`CFRunLoopRunInMode` 带超时循环，`stop()` 先 `CGEvent.tapEnable(false)` 再停 run loop），锁里只有「指针下方的小窗矩形」这一份共享状态，其余状态只在 tap 线程读写，识别到键就回调（`EnhancedMode` 负责 `DispatchQueue.main.async` 切回主线程）。只登记 `keyDown` 和 `flagsChanged`：fn + P 吞掉并触发「PiP 当前窗口」，fn + ⇧ + P 触发「框选区域」；不带 ⌘⌃⌥、也不带 fn、且 `event.location` 落在某个小窗矩形里时拦截 `= / - / F / D / ⌫`（主键盘和小键盘的加减、两个删除键），按住 F / D / ⌫ 只算按下那一次，缩放键可以连发，其余按键一律原样放过去。fn 轻点用 `flagsChanged` 的按下 / 松开时间差（0.4 秒内，期间没按别的键或修饰键；按下 fn 时已经按着别的修饰键 / 普通键，或期间出现修饰键变化都作废）识别，作用在指针下方的小窗上（隐藏起来的也算，这样轻点 fn 能把藏起的小窗叫回来）——隐藏 / 显示走 `HoverHider.toggleManualHide()`，和悬停隐藏共用「淡出 + 点击穿透 + 移开或 ⌥ 轻点恢复」，悬停自动隐藏关着时也能用（隐藏期间照样有 0.05 秒一次的检查）。悬停裸键的命中区由 `PiPManager.refreshHotKeyRects()` 灌进 tap（只算看得见、没被悬停隐藏的小窗，坐标转成左上角原点）；打开、关闭、拖动、缩放、悬停隐藏时都会刷新。权限按 `ClickTrigger` 的模式处理：开关刚打开且没有辅助功能权限时用系统授权框提示一次（本次运行只提示一次，之后只给文字提示），开启期间每秒复查一遍权限，授权后自动装上 tap，运行中被撤销就拆掉 tap 并提示一次；关掉开关立即移除 tap 和检查定时器。
- **首启引导浮层**：欢迎窗口关掉后（只有第一次启动），在菜单栏图标下面显示一张带箭头的卡片（`GettingStarted`，`PipDog.gettingStartedShown` 记下已看过）。浮层是一个铺满图标所在屏幕的 borderless 窗口（`CGShieldingWindowLevel`，所以一定在小窗上面），内容是一层很淡的暗色 + 图标高亮框 + 箭头 + 卡片；卡片是 SwiftUI 的 `GettingStartedView`，只吃 `GettingStartedInfo` 纯数据，不读设置。整块窗口都接收点击，点一下任意处就关（卡片本身 `hitTest` 返回 nil，点它也算点到背景）。图标位置由 `StatusMenu.statusItemScreenFrame` 给（按 statusItem 的按钮换算成屏幕坐标，贴不到菜单栏顶边时返回 nil，那就等一拍再试一次）。菜单「显示上手指引」随时重放：菜单先关掉，0.15 秒后再显示。启动时的提示顺序是：使用说明（第一次启动）→ 首启引导浮层 → 上次退出没放回的窗口 → 3 秒 → 没生效的快捷键；浮层会接管点击，所以点它一下就继续后面的提示，不会出现两个浮层叠在一起。
- **原 app 退出后重连**：抓取结束先按 `SourceWindowHealth` 判断：app 进程还在、只是窗口关了 → 照旧关闭小窗（用户暂停、最小化暂停时每秒的检查也会发现，照同样方式结束）；app 和窗口都还在、只是窗口不在当前桌面（最小化、别的 Space）→ 保持暂停，不关小窗，窗口回到当前桌面后自动重新开始抓取；app 退出了 → 小窗不关，画面停在最后一帧并盖上「等待「app」重启」的占位提示，进入重连状态（`SourceWindowReconnector`，2.5 秒一次的 `Timer.scheduledOnCommonModes`，最多等 5 分钟）。每轮用 `SCShareableContent` 查同一 bundle ID 的 layer 0 窗口，按「同一个 windowID → 标题（去首尾空白后）完全相同 → 尺寸接近（±15%）且只有一个候选」挑一个，宁可继续等也不接错窗口（没有可用线索、又有多个候选时返回 nil）。找到后用新 `SCWindow` 新建一个 `WindowCapture`（区域 PiP 把原区域按新窗口裁剪，裁空了继续等），启动成功才把面板换成新窗口的身份：`PiPManager` 把 `panels` 的 key 换成新的 windowID（`PiPKey` 里的区域换成裁剪后的区域，位置记忆跟着迁移）、把记住的面板位置和 `SourceWindowActivator` 的停放记录一起改到新窗口 ID 上（停放记录换成新进程的 pid、丢掉旧进程的 AX 窗口，进行中的停放和「移完再放回」标记一起改到新 ID）。新窗口上如果已经有另一个 PiP（同一 app 两个整窗 PiP 挑到同一个窗口），后来这个照常关闭，不覆盖已有面板；旧、新 ID 都指向同一个窗口，判断「最后一个 PiP」时两个都要看，`closeAll` 也不会漏掉。`onMoved` / `onClose` 回调不再捕获创建时的 key，而是现查（`key(for:)`），避免换 key 后位置记错、关窗时找错窗口。`SourceWindowReconnector.stop()` 只停定时器、不丢回调，所以启动失败 `resumeWaiting()` 接着等、超时关闭都仍然有效。启动失败就继续等下一轮，不关小窗也不报错。等满 5 分钟、或用户关掉小窗，才走正常的 `PiPPanel.close()`（`onClose` → 从 `PiPManager` 移除 → 恢复停放的窗口）。等待期间拖动、吸附、悬停隐藏照常可用，点一下小窗会立即再查一次；重连后缩放复位到 1 倍，新窗口宽高比不同时面板尺寸跟着调整。
- **渲染卡顿分级恢复**：`RendererWatchdog` 只看「按当前帧率最多应该多久来一帧」和「上一帧什么时候到的」，判定阈值 = max(2 秒, 期望间隔 × 5)。第 1 级 `setNeedsUpdate()` 重新下发配置，第 2 级先确认窗口还能抓（`WindowLocator.shareableWindow`），确认之后才 `stopCapture` + 重新 `startCapture`（离开 running、停掉旧流、确认没被关掉，再 `start(fps:)`；窗口暂时不在 on-screen 列表里（最小化、别的 Space）时不停流、不改状态，`retryRestart` 让 watchdog 停在这一级隔一个阈值再试，不升级成「提示用户」；重建本身失败就按抓取失败结束，交给面板提示并关闭），第 3 级才 `Feedback.show` 提示画面卡住、已经尝试恢复；每级之间至少隔一个阈值，有帧到达就回到正常监控。帧到达按 ScreenCaptureKit 送来的任意 sample buffer 算（包括画面没变的 idle 帧，由 `FrameMailbox.noteArrival` 在帧回调里记时间），所以静止窗口不会被误判；静止降帧、被遮挡 1 fps、窗口最小化、截图和暂停状态下完全不监控。周期检查挂在原来 1.5 秒的 `sourceTimer` 上，不另开定时器。
- **Chromium / Electron 停帧提示**：这类 app 的窗口移到别的桌面、或被完全遮挡后可能停止重绘，ScreenCaptureKit 只拿到最后一帧。`ChromiumRenderHint` 只在画面已经停住 2 秒后才每秒看一次源窗口是否真的看不见（`WindowLocator.isFullyVisible`：不在当前桌面的窗口列表里，或被前面的窗口按 5 × 5 采样完全盖住；和 PiP 面板的可见性判断共用 `Geometry.isCovered`），移回后 2 秒内连一帧都没再到达才提示（按 `FrameMailbox.noteArrival` 记的任意帧算，idle 帧也算：静止的页面本来就只发 idle 帧，只看画面内容会把「切 Space 回来」误判成停画；宽限期内又看不见就回到等它回来）；app 名单加 bundle 前缀见 `SourceAppCompatibility`，同一个 app 每次运行只提示一次。兼容模式（`PipDog.chromiumCompatibilityMode`，默认关）打开时提示换成「退出这个 app，带 `--disable-backgrounding-occluded-windows` 重新打开」；本项目不重启、不退出任何 app。
- **小窗**：拖动画面移动（画面放大时是平移）；拖右下角的手柄等比缩放（不会拖出屏幕可见区域）。抓取分辨率跟着小窗的像素尺寸走（长边最多 4096），不按原窗口的原生分辨率抓，省内存和 CPU；放大时抓的是当前可见的那块区域，最多到它的原生分辨率。原窗口改变大小或移到缩放比例不同的屏幕时，画面和小窗的宽高比会自动跟着调整；区域 PiP 在原窗口变小时会裁剪到窗口内，窗口变回来后恢复原区域。原窗口关闭后小窗会自动关闭并提示（即使画面静止、或用户暂停 / 最小化暂停着，也会在约 2 秒内发现）；原 app 退出时小窗不关，等它重启后重连（见上）。抓取因屏幕录制权限被撤销而中断时，小窗关闭并给出授权引导，其他意外中断只提示「画面抓取意外停止」。
- **帧率与省电**：设定帧率 = 这个 app 的记录帧率，没有记录时用全局默认（`AppFrameRateSettings.frameRate(forApp:)`）。实际帧率取它的最低值：画面连续约 5 秒没变（相邻帧的 64 × 64 抽样灰度指纹相同）降到 1 fps，面板被其他窗口完全遮挡或不在当前桌面时也降到 1 fps；一有变化 / 重新可见立刻恢复。两项都在 `WindowCapture` 里，只改状态后走 `setNeedsUpdate()` → `makeConfiguration()`（`minimumFrameInterval`），不重建流。指纹在帧回调已有的主线程投递里算（一帧 4096 个采样点，不建 Task、不跨线程碰像素，只认 32BGRA，算不出指纹就当有变化）。遮挡用 `CGWindowListCopyWindowInfo` 的前后顺序加 5 × 5 采样点判断（不在当前桌面的窗口列表里也算不可见），PipDog 自己的窗口（提示浮层、设置窗口）不算遮挡。截图（快速查看）期间用设定帧率，免得等一帧等太久。
- 出错（找不到窗口、区域太小、抓取失败等）时，屏幕顶部会出现一个几秒后自动消失的提示。
- 菜单栏里的菜单项同样可以触发这些功能，菜单上显示的是当前生效的快捷键。
- **第一次启动**：显示一次「欢迎使用 PipDog」窗口，分三块：快捷键（键帽样式，按当前设置）、小窗操作（两列图标网格，按当前的单击 / 双击和悬停隐藏设置）、权限（屏幕录制和辅助功能各自是否已授权）。按钮「打开设置」「开始使用」（回车），Esc 关闭。以后可以从菜单「使用说明…」再看；菜单里还有「显示上手指引」（重放菜单栏引导浮层）和「关于 PipDog」（版本号）。启动时不弹权限框；欢迎窗口关掉后依次是首启引导浮层、上次退出没放回的窗口、启动时没注册上的快捷键（都用浮层 / 屏幕顶部提示）。
- **快捷键没生效**：启动时有快捷键注册失败，会提示一次是哪个组合（已被其他 app 独占时会说明），请在设置里换一个；设置里对应的那一行也会显示红字。
- **原窗口最小化**：盖上「原窗口已最小化，画面暂停」提示（约 1 秒内出现，需要辅助功能权限才能判断是不是最小化；没有权限时不提示），从程序坞恢复原窗口后自动去掉：最小化期间系统可能已经停了抓取，面板会自己重新找到窗口并开始抓取（复用 `resumeAfterUnhide()`），不需要点小窗。原窗口在其他桌面（Space）时不提示，小窗照常显示系统给的画面。如果系统因为原窗口不在当前桌面停掉了抓取，小窗会关闭并提示恢复原窗口后再 PiP 一次；抓取中途停止时，如果是屏幕录制权限被撤销（启动时有权限、现在没有），会走权限引导。

### 设置
- **全局快捷键**：点击某个动作右边的按钮开始录制，按下新的组合键即可，立即生效、无需重启。组合键至少要包含 ⌘、⌃ 或 ⌥（只有 ⇧ 不行），并且不能只用 ⌘ 或 ⌘⇧ 加普通按键（会抢走 ⌘C、⌘Q、⌘W 这类常用快捷键；F1–F20 除外）；录制时按 Esc 取消，切到别的 app 或设置窗口失去焦点也会自动取消；点 × 清除，清除后该动作没有快捷键，但仍可从菜单使用。录制期间全局快捷键会暂停，所以可以重新录当前的组合。
- **冲突**：同一个组合不能分配给两个动作。和其他 app 的全局快捷键冲突检测不出来（macOS 允许多个 app 注册同一个组合，注册不会失败，按下时由系统决定谁收到），被系统自己占用的组合（如 ⌘ 空格）也检测不出来；按了没反应时请换一个组合。注册真的失败、或全局快捷键功能本身初始化失败时，会在那一行下面显示红字和错误码，这时只能从菜单使用。
- **键盘控制**：设置窗口「键盘控制」一栏的开关，默认关，存 `PipDog.enhancedMode`（原始 Bool）。打开时如果没有辅助功能权限，用系统授权框提示一次（本次运行只提示一次），授权后自动可用；关掉时立即拆掉键盘 tap，不装任何监听。键位：fn+P / fn+⇧+P 等价于两个全局快捷键，指针停在小窗上时 =、- 缩放，F 切帧率，D 开关静止降帧，轻点 fn 隐藏 / 显示，⌫ 关闭（缩放可以按住连发，F / D / ⌫ 按住只算一次）。F 和 ⌫ 在控制条上有对应按钮；缩放、静止降帧开关和 fn 隐藏没有。
- **修饰键 + 双击**：可以开关，也可以选择需要按住哪些修饰键（⌃ ⌥ ⇧ ⌘，至少一个）。默认 ⌥⇧（旧版本默认是 ⌃⌥；已经保存过设置的用户保持原来的设置不变）。按住 ⌃ 点击时 macOS 会把第一次点击当成右键，所以不推荐包含 ⌃。
- **帧率**：PiP 画面每秒刷新次数，可选 5 / 10 / 15 / 24 / 30 / 60 fps，默认 10。修改后立即应用到已打开的 PiP。帧率越高越流畅，CPU 占用也越高。没有按 app 记录的 app 用这个全局值（`PipDog.captureFrameRate`）。
- **按 App 记住帧率**：打开 PiP 时用源 app 的帧率记录，没有记录时用全局默认；终端、编辑器类 app（Terminal、iTerm2、VS Code、Sublime Text、JetBrains 全家桶、Xcode、Cursor、Windsurf、Zed、活动监视器、控制台等，见 `AppFrameRateSettings.lowFrameRateBundleIDs`）第一次打开时记为 5 fps。记录存在 `PipDog.perAppFrameRates`（bundle ID → fps 的字典，只认上面那几个档位，旧值/手改坏的档位按没有记录处理）。设置窗口「画面」一栏的列表显示已有记录（app 名、帧率、删除），改完立即应用到这个 app 已打开的小窗；删掉记录就回到全局默认。
- **静止降帧 / 遮挡暂停**：同在「画面」一栏，各存一个键（`PipDog.reduceFrameRateWhenStatic`、`PipDog.pauseWhenObscured`，没有保存过时为开）。恢复默认会把它们改回开，并清空按 app 的记忆（全部回到全局帧率）。
- **Chromium 兼容模式**：同在「画面」一栏，默认关，存 `PipDog.chromiumCompatibilityMode`（原始 Bool，没有保存过时为关）。只改提示里的建议（是否让用户带 `--disable-backgrounding-occluded-windows` 重新打开 app），不改抓取行为，也不会替你重启任何 app。
- **小窗点击**：设置窗口「小窗」一栏选「单击」或「双击」切回原窗口 / 移到屏幕边上，默认双击（拖动或随手点一下不会误触发）。改了立即对已打开的小窗生效。⌥ + 单击快速查看不受影响。保存在 UserDefaults 的 `PipDog.windowClickMode`（`single` / `double`）。
- **不透明度 / 悬停时自动隐藏**：同在「小窗」一栏，改了立即对已打开的小窗生效。不透明度存在 `PipDog.windowOpacity`（0.3–1.0，没有保存过时 1.0），悬停隐藏存在 `PipDog.hoverAutoHide`（没有保存过时关闭）。悬停隐藏只是临时淡出，不改保存的不透明度。
- **开机时启动**：设置窗口「通用」一栏和菜单栏里的「开机时启动」都可以开关，用的是系统登录项（`SMAppService.mainApp`），状态以「系统设置 › 通用 › 登录项与扩展」为准，PipDog 不另外保存；你在系统设置里改过后，回到 PipDog（或打开设置窗口、菜单）时会重新读取。启动时不会自动登记。系统要求你先允许时，设置窗口会显示说明和「打开登录项设置」按钮，从菜单打开时直接打开那个页面。PipDog 需要装在「应用程序」文件夹里（从临时构建目录运行时可能提示找不到可登记的应用）。
- **语言**：设置窗口「通用」一栏的「语言」选跟随系统 / English / 简体中文（语言名用各自的语言显示）。写的是 app 自己域里的 `AppleLanguages`（`["en"]` 或 `["zh-Hans"]`；跟随系统时删掉这个键），读取时只看 app 自己的域（`persistentDomain(forName:)`），不看全局的系统语言列表。macOS 在启动时读取语言，所以改了以后弹框提示「立即重新启动」，重新启动用的是屏幕录制授权后同一个 `Permissions.relaunch()`。跟随系统时由系统按首选语言列表在 en / zh-Hans 里挑：列表里先遇到简体中文就用中文，否则用英文（繁体中文也用英文）。
- **恢复默认**：恢复上面表格里的默认快捷键、双击设置、帧率（10 fps）、两个节能开关（都恢复为开，并清空按 App 记住的帧率）、Chromium 兼容模式（关）、小窗点击方式（双击）、不透明度（100%）、悬停时自动隐藏（关闭）、键盘控制（关闭）和语言（跟随系统，有变化时提示重新启动）；不改开机时启动，也不把「已看过首启引导」的标记改回去。
- 设置保存在 UserDefaults（`com.hwj.PipDog` 的 `PipDog.shortcutConfig`、`PipDog.captureFrameRate`、`PipDog.perAppFrameRates`、`PipDog.reduceFrameRateWhenStatic`、`PipDog.pauseWhenObscured`、`PipDog.chromiumCompatibilityMode`、`PipDog.windowClickMode`、`PipDog.windowOpacity`、`PipDog.hoverAutoHide`、`PipDog.enhancedMode`、`PipDog.onboardingShown`、`PipDog.gettingStartedShown`，以及语言用的 `AppleLanguages`），启动时读取；没有保存过时用默认值。读取是宽容的：缺少的字段用默认值，单个坏掉的快捷键（或不带修饰键的快捷键）只丢掉那一项。
- 设置窗口宽 480 pt，默认高 600 pt（不超过屏幕可用高度减 100 pt，最低 320 pt），可以上下拉高或缩矮；内容比窗口高时 Form 自己滚动，「恢复默认」固定在底部。`NSHostingController.sizingOptions` 只取 `.minSize` / `.maxSize`，不要让窗口按内容的理想高度撑开（那样会比屏幕还高、也没法滚动）。
- 设置窗口打开期间 PipDog 会临时显示 Dock 图标，这样窗口能稳定地出现在最前面；关闭设置窗口后 Dock 图标消失。从菜单或 ⌘, 打开（包括再次打开、窗口被最小化过）时，设置窗口总会出现在其他 app 的窗口上面，不用再点 Dock 图标；设置窗口始终只有一个。关掉设置窗口后，前台还给打开设置前的那个 app（它已退出时 PipDog 只让出前台）。

## 目录
- `Config`：签名配置（xcconfig）
- `Design`：图标原图和生成它的脚本
- `docs`：开发说明（本文件）
- `scripts`：打包脚本
- `PipDog/App`：入口、菜单栏、权限检查和提示
- `PipDog/PiP`：PiP 管理（面板字典、拖动吸附、源 app 重启后换 key 重连）、浮窗面板和内容视图（单击 / 拖动、缩放平移、悬停 ×）、悬停自动隐藏、缩放手柄、窗口抓取（区域和放大的 `sourceRect` 裁剪、跟随窗口尺寸、静止降帧与遮挡暂停、渲染卡顿分级恢复）、重连匹配（`SourceWindowReconnector`）、渲染看门狗（`RendererWatchdog`）、Chromium 停帧判断（`SourceAppCompatibility`、`ChromiumRenderHint`）、源窗口健康判断、可见性判断、切回原窗口、快速查看截图
- `PipDog/Settings`：快捷键设置（存储、注册、录制）、帧率 / 按 app 记住的帧率、Chromium 兼容模式、语言设置、设置界面和设置窗口激活
- `PipDog/Resources`：Info.plist（生成）、entitlements、图标、String Catalog（`Localizable.xcstrings`、`InfoPlist.xcstrings`）
- `PipDog/Input`：全局快捷键、框选遮罩、修饰键 + 双击（CGEventTap）、AX 元素查找
- `PipDog/Support`：坐标系换算（左上角 ↔ 左下角原点）、窗口定位、提示浮层
